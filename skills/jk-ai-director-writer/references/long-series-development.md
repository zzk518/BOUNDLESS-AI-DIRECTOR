# 长剧集开发与长期资产

长剧集不是“写很多集”，而是让人物、世界和欠账在多轮创作中可追踪、可回滚、可传播修改。

## 开发顺序

1. **系列发动机**：每集为何能产生新问题，又为何仍属于同一部作品。
2. **季度命题**：本季不可逆改变什么；结尾关闭什么、打开什么。
3. **分集发动机**：本集欲望、阻力、变化、独立回报和牵引。
4. **长期资产**：在写第一集前建立最小可用版本，之后增量维护。

## 最小资产库

### 人物圣经

人物 ID、公开身份、私下需求、可观察习惯、能力边界、价值底线、秘密、关系状态、声纹、季初/季末状态、不可逆事件、最近更新时间。

### 世界与设定库

地点、机构、技术/制度规则、资源与代价、例外、公众认知、真实状态、首次展示、允许改变的条件。规则只能通过已登记代价或事件改变。

### 时间线与关系状态

每个事件登记剧内日期、集数/场次、参与者、前置条件、结果。关系用状态变化而非“好/坏”记录：信任、债务、权力、亲密、敌意各自可增减。

### 信息与伏笔账本

```yaml
setup:
  id: SET-001
  planted_at: E01-S03
  visible_fact: ""
  intended_reading: ""
  alternate_reading: ""
  payoff_window: E04-E06
  payoff_type: reveal|choice|image|consequence
  status: planted|reinforced|paid|retired
```

### 变更日志

每次修改记录：版本、变更、证据、影响人物/集/场/伏笔、需要回写的资产。旧版不覆盖；明确当前生效版本。

## 分集写作循环

1. 读取本集所需的最小资产范围。
2. 写“进入状态”和本集允许改变的项目。
3. 完成本集结构和剧本。
4. 连续性审计：人物、时间、知识、规则、道具、伤病、关系。
5. 只把剧本中实际发生的事实写回资产；计划但未写入正文的不升级为正史。
6. 输出本集状态差异和下一集欠账。

## 伏笔与长期悬念规则

- 伏笔必须先作为自然场景事实成立，不能只为未来服务。
- 强化次数与显眼度成反比；越明显越少重复。
- 超过回收窗口未回收时，明确选择延期、改写或退休。
- 回收应改变人物选择或观众理解；单纯解释名词不算回收。

## 长期验收

- 系列发动机至少能举出 5 个机制不同的分集例子；
- 任一角色当前状态可从日志追溯到具体场次；
- 任一世界规则都有代价、例外和证据；
- 任一伏笔都有状态和回收窗口；
- 局部改稿能列出传播范围，不靠记忆猜测。
